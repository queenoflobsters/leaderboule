# AGENTS.md

Leaderboule is a single Rust binary crate: Dioxus 0.7.10 fullstack + SeaORM 2 + PostgreSQL 17.
`README.md` is the setup/deploy reference; the notes below are the non-obvious parts.

## Project shape

- `src/main.rs` has two entrypoints selected by `feature = "server"`: Axum server vs wasm client.
- `src/api/` is shared client/server code and contains the `#[server]` functions. `src/server/` is server-only; `src/client/` is the UI.
- SeaORM/tokio/uuid/argon2 are only available for non-wasm targets. Do not import them from shared or client code.
- Dioxus is pinned to `=0.7.10`; the Dockerfile installs the matching Dioxus CLI.
- `src/server/elo.rs` implements the custom Pétanque Elo engine documented in `ELO_SYSTEM.md` (team dispersion, margin-of-victory, dynamic placement, individual weighting). Pure unit tests live in the same file and run with `cargo test --no-default-features --features server`.
- User-facing copy and most comments are French; keep that language unless asked otherwise.

## Commands

```bash
# Database for local development
docker compose up -d postgres
podman-compose up -d postgres

# Dev server (loads .env via dotenvy)
dx serve

# Fast verification
cargo check --all-targets
cargo check --target wasm32-unknown-unknown --no-default-features --features web
cargo clippy --all-targets
dx check --web

# Full web + server bundle (also validates assets/CSS)
dx build --web --release
```

- `cargo fmt --all` is **not** currently clean and rewrites unrelated files. Format only files you touched.
- `cargo test --no-default-features --features server` runs the pure Elo unit tests. There are still no DB integration fixtures.
- Unknown-email login calls the real Helloasso API. For local auth tests, seed users directly in PostgreSQL instead.

## Database

- `DATABASE_URL` must be a full `postgres://user:password@host:port/database` URL.
- Schema lives in `src/init.sql`; it is embedded with `include_str!` in `server/db.rs` and executed only when the `users` table is absent.
- There is no migration system: the database is created from scratch, and restarting the app does not replay `init.sql`.
- The connection and schema bootstrap are lazy: `server/db.rs::get()` runs on the first DB access, not at server boot.
- Editing `src/init.sql` does **not** update an existing database. For dev, reset the Postgres volume (for example `docker compose down -v`).
- `games_lost` and `win_ratio` are PostgreSQL generated columns; `best_elo` is maintained by a trigger. Do not write those columns through SeaORM.
- Moderation adds `users.role` / `users.status` and the `activity_logs` / `audit_logs` tables. `UserRole` and `UserStatus` are shared enums mapped to text columns by SeaORM.
- `ADMIN_EMAILS` is a comma-separated list of emails that are always admin (case-insensitive). They are synced to `role = 'admin'` at DB init and on login, and the moderation code refuses to demote or sanction them.
- Helloasso reads `HELLOASSO_CLIENT_ID`, `HELLOASSO_CLIENT_SECRET`, `HELLOASSO_SLUG`, and `HELLOASSO_FORM_SLUG` with `unwrap()`; missing values panic on the first Helloasso login. The compose files currently forward only the client id/secret, so add the two slug variables when testing containerized login.

## Frontend / CSS

- There is one global stylesheet: `assets/style/main.css`, imported once in `src/client/route.rs`.
- Do not add per-component `document::Stylesheet` imports or Tailwind. Tailwind was removed.
- The static landing page is separate: `public/landing.html` + `public/style.css`. The server reads `public/landing.html` relative to the working directory.
- `src_txt/` is generated by `./cp_mv.sh`, gitignored, and must not be edited.

## Build / deploy gotchas

- The release profile must keep `strip = "debuginfo"`. `strip = true` breaks `dx bundle`/wasm-bindgen on the current toolchain.
- The Dockerfile deliberately builds a dummy app to cache dependencies, then deletes **all** `leaderboule*` artifacts and `target/dx` before the real build. Do not simplify steps 9-12 or remove the final `grep` assertions; otherwise the dummy app can be shipped.
- `podman-compose up --build` does not recreate a container when only the image changes. Use `podman-compose up --build --force-recreate`, or `podman-compose down` then `up --build`. Check `podman ps` if the served asset still looks old.
- `compose-infra.yaml` is the production/Traefik path: it pulls the CI-built `latest` image, needs the external `traefik-network`, and expects `HOST`, `POSTGRES_*`, and Helloasso env vars.
- CI only builds/pushes the Docker image on the default branch; there is no test stage.
